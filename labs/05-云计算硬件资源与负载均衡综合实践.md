## 任务三：三 DataNode 与 HDFS 副本容错（25分，45分钟）

### 3.1 初始化并启动

实验一与多节点实验使用相同的9000/9870端口，不应同时运行。

```bash
bash scripts/stop-hdfs.sh
bash scripts/multinode/setup-multinode.sh
bash scripts/multinode/start-multinode.sh
bash scripts/multinode/status-multinode.sh
```

确认报告中出现 `Live datanodes (3)`；如果没有，请等几秒再查看状态并保留输出。

### 3.2 上传并观察副本

```bash
source scripts/multinode/activate.sh
hdfs dfs -mkdir -p /multilab/input
hdfs dfs -put -f data/hello.txt /multilab/input/
hdfs dfs -ls /multilab/input
hdfs fsck /multilab/input/hello.txt -files -blocks -locations
```

观察 `Average block replication: 3.0`、`Live_repl=3` 及三个 DataNode 的数据位置。文件很小、只有一个Block属于正常现象。

### 3.3 停止一个 DataNode 并验证读取

```bash
bash scripts/multinode/stop-one-datanode.sh 2
bash scripts/multinode/status-multinode.sh
hdfs dfs -cat /multilab/input/hello.txt
```

等待NameNode检测心跳中断后，应看到 `Live datanodes (2)`，文件仍可正常读取。如果状态尚未更新，等待20秒再查一次。

### 3.4 恢复节点

```bash
bash scripts/multinode/start-one-datanode.sh 2
bash scripts/multinode/status-multinode.sh
```

观察 `Live datanodes (3)` 是否恢复。截图：3节点、3副本、2节点、故障后读取。

**思考：** 与RAID 1比较，HDFS多副本保护的故障范围有何不同？这里的三个DataNode位于**同一个Codespace**，不能把它们描述为三台独立物理服务器或三个独立故障域。

## 任务六：负载均衡（15分，40分钟）

本仓库提供一个**仅供教学的 Python 标准库演示**，不需要Nginx，也不需要购买云服务器。三个后端监听 `8101/8102/8103`，负载均衡器监听 `8080`，各服务都运行在**同一个Codespace**中。

### 6.1 启动并查看状态

```bash
bash scripts/loadbalance/start-lb.sh
bash scripts/loadbalance/status-lb.sh
```

预期看到 `balancer (8080): UP`，以及 `server-A/B/C: UP`。

### 6.2 六次请求观察轮询

```bash
bash scripts/loadbalance/test-lb.sh normal
```

正常应依次有A/B/C三个服务响应，结尾显示 `PASS: normal`。记录请求响应序列，说明为什么轮询能够分配请求。

### 6.3 模拟Server B故障

```bash
bash scripts/loadbalance/stop-server.sh B
bash scripts/loadbalance/status-lb.sh
bash scripts/loadbalance/test-lb.sh failover
```

预期Server B显示 `DOWN`，但A和C仍可处理请求，并显示 `PASS: failover`。本演示在转发请求时探测后端可用性，并在当前后端不可达时尝试其他后端。

### 6.4 恢复Server B

```bash
bash scripts/loadbalance/start-server.sh B
bash scripts/loadbalance/test-lb.sh recovered
```

正常应显示 `PASS: recovered`。截图：三个服务在线、轮询结果、B下线后依然服务、恢复后结果。

### 6.5 清理

```bash
bash scripts/loadbalance/stop-lb.sh
```

若看到 `Address already in use`，先执行上述停止脚本，重新启动。不要直接结束整个Codespace。

**思考：** 请解释轮询与故障转移的区别；为什么后端都在同一Codespace时，不能宣称能够抵御整台物理服务器故障？
